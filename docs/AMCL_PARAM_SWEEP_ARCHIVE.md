## 一、实验目的与判据

### 1.1 目的

M3 阶段要对比「纯 `/odom`（A 组）」与「EKF 融合输出（B 组）」的定位误差。该对比成立的前提是 `/odom` 必须是**会漂的估计值**。`/odom` 数据源已于 2026-11-10 从 WORLD（直取世界位姿）切换为 ENCODER（编码器积分），A 组条件成立（详见 `docs/VERIFY_ODOM_SOURCE.md`）。

在此前提下，本组实验要回答的是：**AMCL 的观测模型与运动模型参数，哪些与仿真实际状态不匹配，改动后定位精度是否真的改善。**

### 1.2 判据（测试前写死，避免事后找理由）

| 判据 | 内容 |
|:---|:---|
| 有效性 | 10 个航点全部成功、无恢复行为触发、无位置跳变 |
| 改善 | 更新时刻口径的位置误差均值与分位数同时下降，且 yaw 误差不上升 |
| 恶化 | 出现跟丢、位置跳变、恢复行为（Spin/BackUp）、航点失败 |
| 单变量 | 每轮只改一组参数，其余全部保持上一轮值 |

## 二、实验方法

### 2.1 链路一致性

脚本 `scripts/run_amcl_test.sh` 启动的是**项目原有巡航链路** `ros2 launch autopartol_robot autopartol.launch.py`，即 10 个固定航点、单轮循环、失败重试 2 次、单点 60 s 超时。不自造简化驱动，保证数据与批量实验 `patrol_runs.csv` 可比。

### 2.2 数据采集

| 文件 | 内容 |
|:---|:---|
| `pose_trace.csv` | 每 0.5 s 一行：`t_sec, gt_x, gt_y, gt_yaw, amcl_x, amcl_y, amcl_yaw` |
| 真值来源 | `/gazebo/model_states`（唯一真值来源，非 `/odom`） |
| `bt_log.txt` | 订阅 `/behavior_tree_log`，恢复行为（Spin/BackUp/Clearing）变成可 grep 的记录 |
| `params_snapshot.txt` | `ros2 param get` 抓运行时真实生效值 + yaml md5，用于证明本轮配置未静默失效 |
| `patrol.log` | 巡航节点终端输出，含每点语音时间戳与最终汇总 |
| `summary.txt` | 收尾时按 `pose_trace.csv` 计算的末点误差与全程误差 |

### 2.3 口径说明（本组实验最重要的方法论产出）

`/amcl_pose` 是**阶梯状**的：只有自身估计位移超过 `update_min_d: 0.25` 或转角超过 `update_min_a: 0.2 rad` 才更新一次。真值每 0.5 s 连续采样，两者之间必然出现「车在走、估计不动」的空档。

**因此存在两种口径，不可混用：**

| 口径 | 定义 | 性质 |
|:---|:---|:---|
| 全样本口径 | 所有采样点统计 | 混入「更新门限阶梯滞后」，极值指标被污染，跨组不可比 |
| 更新时刻口径 | 只在 `/amcl_pose` 数值发生变化的时刻统计 | 排除阶梯，但仍含一截滞后（触发条件是估计位移而非真值位移） |

**结论：`summary.txt` 里的「最大位置误差」是阶梯假象，不能作为定位精度上报。** 以 A 组为例，0.433 m 那个点在 t=34.0 s，同一段轨迹：

```
t=33.0  gt=(3.457,1.985)  amcl=(3.319,1.870)   误差 0.18
t=34.0  gt=(3.653,2.145)  amcl=(3.319,1.870)   误差 0.433   ← summary 报的最大值
t=34.5  gt=(3.745,2.221)  amcl=(3.547,2.083)   误差 0.24    ← 更新了，误差回落
```

`amcl` 在 33.0~34.0 之间完全没动，真值走了 0.25 m，差值就是门限量。同理 yaw 误差极值（±17°）全部落在原地旋转段，`update_min_a = 11.5°`，旋转中必然滞后一个门限量。

## 四、逐组分析

### 4.1 A 组（基线）

10 点全成功，无恢复行为，末点 0.033 m / −2.92°。**关键旁证**：本轮 `/odom` 已是 ENCODER 积分（实测 5.1 m 处漂移 1.25 m），末点仍收敛到 3 cm，说明 **AMCL 确实在修正里程计漂移**，融合链路真实工作，不是「odom 本身准所以看着准」。

### 4.2 B 组（`z_hit 0.9 / z_rand 0.1`，有效）

likelihood_field 下单帧观测得分为：

```
p = z_hit * exp(-d^2 / 2*sigma_hit^2) + z_rand * (1 / laser_max_range)
```

`z_rand` 项与粒子位姿无关，是所有粒子共享的常数底噪，唯一作用是抬高差粒子的基础分、压缩好粒子与差粒子的相对差距，即**把似然面压平**。

| | 底噪值 | 相对区分度 |
|:---|:---:|:---|
| A 组 0.5 / 0.5 | 0.5 / 8 = 0.0625 | 与命中项同量级，被压平约一半 |
| B 组 0.9 / 0.1 | 0.1 / 8 = 0.0125 | 放大约 5 倍 |

改善证据（均为单次运行，n=1）：

- 10% 进度抽样均值 0.150 → **0.099**（降 34%）
- 全样本 yaw 误差区间 |max| 17.88 → 14.21（**降 21%**）
- `bt_log` FAILURE 计数 9 → **2**（且仅规划瞬时失败，均自恢复）
- 耗时 207.7 → 198.1 s（降 4.6%）
- 末点 0.033 m 持平；末点 yaw 由 −2.92° 变 +3.95°，**符号翻转、量级同级**，说明不存在系统性航向偏置

预判风险未发生：似然面变尖后**未出现**粒子云锁死、恢复行为、原地打转。

### 4.3 C 组（`alpha1~alpha4 0.05`，失败实验）

**结果：灾难性崩塌，不可用。**

失败时序（`pose_trace.csv`）：

| 时刻 s | 现象 |
|:---|:---|
| 0~78 | 正常，误差 0.01~0.06 m |
| 79~88 | 原地转向 ~180°，yaw 滞后从 28° 增至 41°（A 组同期仅 16°） |
| 88.6 | 误差 0.65 m，首次明显偏 |
| 99~101 | 误差 3.3 m，估计跳入另一块区域 |
| 102.6~117.6 | 原地不动，估计冻结在错误位置达 15 s |
| 118.6 | **0.5 s 内位姿瞬移 3.6 m，yaw 跳 258°** |
| 290.6 | 全程最大误差 9.030 m |
| 末点 | 6.892 m / +107.49° |

**根因：粒子耗尽（particle depletion）。**

```
trans_hat_stddev = sqrt(alpha3 * d_trans^2 + alpha1 * d_rot^2)
rot_hat_stddev   = sqrt(alpha4 * d_rot^2   + alpha2 * d_trans^2)
```

`update_min_a = 0.2 rad` 时，`alpha = 0.05` 给出的航向散开仅 `sqrt(0.05 * 0.04) = 0.045 rad ≈ 2.6°`，而实测 180° 转向的航向漂移约 **40°**。粒子云比真实漂移窄十几倍，真值不在粒子覆盖范围内，激光再准也「看不见」正确解。叠加 `resample_interval: 1`（每次更新都重采样），每轮砍掉一半多样性，几十次更新后 2000 个粒子全挤在同一个错误假设上；`recovery_alpha_slow/fast` 注入的少量随机粒子无法翻盘。118.6 s 那次 3.6 m 瞬移即**滤波器整体切换到另一个错误全局假设**，不是漂移。

**一个被推翻的推理（记录在案）：**

本轮改动前曾判断「实测每 0.4 m 行进偏差 0.098 m，`alpha=0.05` 给出 0.089 m，同量级所以合理」。该推理错误：

- `alpha` 建模的是**每步独立随机噪声**，随步数开方增长、可互相抵消；
- ENCODER 的真实误差是**系统性比例误差**（轮距/轮径比例偏差、轮子打滑），**随距离线性累积、不可抵消**。

正确的比较对象是「一个更新间隔（0.25 m 平移 / 0.2 rad 旋转）内累积了多少偏差」，而非「每 0.4 m 的瞬时偏差」。若航向存在 25% 比例误差，转 180° 就积 45°，与实测 40° 吻合。**结论：仿真里 `alpha` 不该压低，因为仿真里程计误差是系统性偏差而非白噪声。**

> **事后更正（2026-11-23）**：上述 40° 航向偏差的真实来源是 `wheel_separation` 配置错误（0.24 vs 实际 0.36，见 4.5），**不是轮胎打滑**。该错误使 `/odom` 航向按 1.5 倍放大，与 `alpha` 无关。C 组「alpha 不能压低」的结论**仍然成立且更充分**：粒子云 2.6° 的散开面对 50% 的比例误差，必然跟丢。

### 4.4 D 组（B 组复现，`z_hit 0.9 / z_rand 0.1 / alpha 0.2`）

目的：验证 B 组改善不是单次运气（n=1 → n=2）。

| 指标 | A 基线 | B | D（复现） | 判读 |
|:---|:---:|:---:|:---:|:---|
| 10% 抽样均值 m | 0.150 | 0.099 | **0.084** | 两次均低于基线 |
| 全样本最大位置误差 m | 0.433 | 0.474 | 0.391 | 形态一致，均为阶梯假象 |
| 末点位置误差 m | 0.033 | 0.033 | **0.009** | 更收敛 |
| 巡航耗时 s | 207.7 | 198.1 | **199.5** | 两次一致快 4~5% |
| BT FAILURE | 9 | 2 | 7（均自恢复） | 均远低于基线 |
| 恢复行为 | 无 | 无 Spin/BackUp | **无 Spin/BackUp** | 健康 |

**结论：B 组的改善方向在 D 组全部复现**，`z_hit 0.9 / z_rand 0.1` 可定稿（n=2）。但 D 组同样运行在错误的 `wheel_separation` 下，**其 yaw 指标同样失效**（见 4.5）。

D 组还提供一个关键证据：**末点 AMCL 报 108.1°、真值也是 108.1°，yaw 误差 0.00°**，而指令是 90°。说明 AMCL 末点估计完全准确，超调 18.1° 是**车真的多转了**，不是估计错。机理为「判到位瞬间 AMCL 估计仍滞后在 ~90° 附近 → goal checker 据此判成功 → 停车后补正暴露真实偏差」，超调量 ≈ `update_min_a` 门限（11.5°）+ `yaw_goal_tolerance`（8.6°）量级。此项与 `z_hit`、`alpha` 均无关，三次实测（A +20.5°、B +17.0°、D +18.1°）一致。

### 4.5 事后发现的几何错误：`wheel_separation` 0.24 → 0.36

**这是本阶段最重要的一条，它使 A~D 四组的 yaw 指标全部失效。**

#### 几何推导

| 依据 | 值 |
|:---|:---|
| `model.xacro` 左右轮组挂载 | `y = ±0.12` |
| `wheel.urdf.xacro` 轮心相对轮组外移 | `motor_l/2 + shaft_length + wheel_length/2 = 0.03+0.02+0.01 = ±0.06` |
| 轮心实际位置 | `±(0.12+0.06) = ±0.18` |
| **接触点实际间距** | **0.36** |
| 插件配置（修正前） | **0.24**（差 1.5 倍） |
| 轮径 | 插件 `0.10` vs `wheel_radius 0.05` → 自洽，直线不受影响 |

#### 两面后果

`sep` 在差速运动学里同时用于两处：

```
反解轮速：v_L = v - w*sep/2 ,  v_R = v + w*sep/2   ⇒ sep 偏小 ⇒ 两轮差速偏小 ⇒ 物理转向变慢
积分航向：th = (d_R - d_L)/sep                      ⇒ sep 偏小 ⇒ 同样轮程积出更大转角 ⇒ odom 航向被放大
```

- 物理转向速率 = 指令的 **2/3**（发 1.0 rad/s，实际约 0.67 rad/s）；
- `/odom` 航向 = 真实转动的 **1.5 倍**（物理转 60°、odom 报 90°）；
- 两者叠加后 `/odom` 航向恰好与指令一致，于是「里程计看起来挺准」，但真值只有指令的 2/3 —— 这是此前所有旋转段 yaw 误差的系统性来源。

#### 实测验证（`scripts/odom_spin_probe.py`）

发布 0.5 rad/s 转 2 s，同时采 `/odom` 与 `/gazebo/model_states`：

| 比值 | 修正前（预期） | 修正后（实测） | 判读 |
|:---|:---:|:---:|:---|
| `odom / 真值` | 1.500 | **1.055** | 轮距已对齐 |
| `真值 / 指令` | 0.667 | **0.955** | 物理转速恢复 |
| `odom / 指令` | 1.000 | 1.008 | 编码器与指令一致 |

修正后残余 5.5% 为 Gazebo 中的**真实轮胎滑移**（轮子按指令转了，地面没跟上），属正常量级，与配置错误无关。

#### 修正内容

`urdf/parts/plugins.urdf.xacro`：`wheel_separation 0.24 → 0.36`（带完整注释）。`worlds/one.world` 中也有同样的 0.24，但该 world **无任何引用**（实际启动用 `robocup_home.world` + `spawn_entity` 注入 xacro），为死副本，未改动。

#### 对既有数据的影响

| 数据类别 | 是否受影响 | 说明 |
|:---|:---:|:---|
| 位置误差（0.033 / 0.009 m 等） | **不受影响** | 轮径自洽，直线运动与 `sep` 无关 |
| yaw 误差（全部区间与末点值） | **全部失效** | 输入自带 50% 比例误差 |
| 末点航向超调（+17~20°） | 数值失效，机理保留 | 超调量受物理转速影响，需在新基线下重测 |
| 耗时 / 航点成功率 | **弱受影响** | 转向变慢会拖长巡航，修正后应略快 |
| C 组跟丢结论 | 不变且更成立 | 粒子云 2.6° vs 50% 比例误差 |

**处置：A~D 四组保留原样不删，但其 yaw 指标标注失效；下一组起以修正后的新基线（E 组）为准。**

## 六、结论

1. **`z_hit 0.9 / z_rand 0.1` 有效，保留。** 证据：10% 抽样均值 A 0.150 → B 0.099 → D 0.084（两次均低于基线）；BT 失败 9 → 2 → 7（均自恢复）；耗时 207.7 → 198.1 → 199.5 s；末点位置误差 0.033 → 0.033 → 0.009 m；无恢复行为。**n=2 复现，可定稿。** `e_max` 类极值指标因门限阶梯不可比，不作依据。
2. **`alpha1~alpha4 0.05` 失败，回退至 0.2。** 灾难性崩塌（8/10、462 s、6.892 m、9.030 m、Spin 4/BackUp 3），非边际劣化；0.1 无证据安全；0.2 已被 A/B/D 三轮证明可用。此为本阶段**有效负结果**：`alpha` 下压会使粒子云无法覆盖系统性里程计误差，导致粒子耗尽。
3. **评估口径必须固定为「更新时刻统计」。** 否则 `update_min_d/a` 的阶梯滞后会把参数效果整个盖住。`summary.txt` 的最大误差是阶梯假象。
4. **`wheel_separation` 0.24→0.36 是必须先修的几何错误。** 修正前 `/odom` 航向被放大 1.5 倍、物理转速只有指令 2/3，A~D 四组 yaw 指标全部失效。修正后实测 `odom/真值 = 1.055`、`真值/指令 = 0.955`，残余 5.5% 为真实轮胎滑移。**任何 AMCL yaw 参数调优都必须在这项修正之后进行，否则是在给几何错误打补丁**（C 组即为反证）。
5. **末点航向超调（+17~20°）与 AMCL 精度无关。** D 组末点 AMCL 与真值 yaw 完全一致（误差 0.00°），超调是车真的多转了。机理为「判到位瞬间估计滞后 → 判成功 → 停车后补正」，量级 ≈ `update_min_a` 门限 + `yaw_goal_tolerance`。修正 `sep` 后物理转速变快，超调可能进一步增大，需在新基线下重测。
